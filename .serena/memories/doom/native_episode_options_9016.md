# Native episode and options menus (9016)

The NES uses at most 8 sprites per scanline, so full 21-character episode names cannot use the same 8-pixel sprite font on a single line. The 9016 implementation copies A-Z bitmap rows from `tutorial_project/BOOTROM/bootrom_fixr.bin` via `doom/tools/build_native_menu_font.py` into `doom/port/video/native_menu_font.h`. `fcvideo_overlay_episode_menu()` in `doom/port/video/fcvideo.c` writes all three full names directly into the compacted v4 background stream at y=88/120/152, centered with red pixel index3 and a black offset shadow. It sets palette3 and corresponding 16x16 attribute cells. World pixels remain visible under text but their colors shift within those cells. The old episode pair sprite art remains editable but is no longer loaded. Mesen captures: `doom/assets/menu_native_9016/`.

Native options menu labels in `doom/tools/build_native_status_probe.py` now match the compiled engine `OptionsMenu` from `doom/rp2040-doom/src/doom/m_menu.c` with `NO_USE_MOUSE=1`: indices 0 End Game, 1 Messages, 2 Sound. The removed MOUSE overlay label was never a WAD label; it had incorrectly occupied index2 and made Sound look like the Mouse action. The actual engine menu is independent of WAD text. `doom/sim/mesen2/run_native_status_probe.py --menu --menu-id 2` and `--menu-id 4` test both paths. Stamp `20DOOM-04-9016`.

Run `doom/tools/reproduce_native_hud.sh --verify-twice` from the repo root to regenerate the panel/menu font headers, run 34 Python tests and 2 host C tests, capture five Mesen scenes, build two device trees, and compare ROM/UF2 bytes. Default output and flashable artifact path are under `/tmp/fcpico-native-hud-repro/`; override with `OUTPUT_DIR=/path`. The root README documents this as the simple artifact rebuild route.
