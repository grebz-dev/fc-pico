# Native HUD layout visual prototypes (2026-09-30)

Branch `prototype/hud-reference-variants`, commit `5a1a395`, contains four actual Mesen-captured static NES mapper-0 HUD fixtures. Run `doom/.venv/bin/python doom/tools/prototypes/hud_reference_variants.py`. Comparison/report: `doom/assets/hud_layout_variants/README.md` and `comparison.png`. Each `A`–`D` folder has real 256x240 `mesen.png`, 4x HUD crop, ROM, CHR, nametable, palette, OAM and metrics. Source layout is `doom/assets/hud_edit_reference/full-frame-reference-edited.png`; the preferred 24x24 `doomguy_faces.png` was nearest-neighbor scaled to 32x40, with all 42 normalized states exported.

A: 8x8 sprite face/ARMS/keys + one HUD BG palette, 29 OAM, peak 8/scanline, visually closest. B: global 8x16 sprites, 18 OAM, peak 8; lower ARMS row shifted four pixels to pair. C: face in warm BG palette, ARMS/keys sprites, 9 OAM, peak 4; consumes second HUD BG palette. D: all BG, 0 OAM; requires 16-pixel-aligned key strip and changes armor area. Mesen `RemoveSpriteLimit=false`. These are static NROM fixtures, not fc-pico stream cosimulation or hardware validation. Current v4 transport omits y224..231 columns2..29; dynamic face/number/key content needs further integration work. See `mem:doom/native_ui` for current production protocol/UI architecture.

## Dynamic ARMS/key refinement (2026-10-01)

Commit `35daa74` on the same prototype branch adds `doom/tools/prototypes/hud_playback_candidates.py` and `doom/assets/hud_playback_candidates/`. Three real Mesen playback ROMs (`digit`, `plate`, `border`) switch HUD states at frames 60 and 120; 256x240 screenshots captured at frames 30, 90, 150 show changing ammo, health, armor, selected weapon, inventory/current-max values, key availability, and face (`STFST00`, `STFOUCH2`, `STFEVL3`). All three keys use one exact 8x8 mask with different sprite palette colors. ARMS uses consistent 9x10 wells and either yellow selected digit, yellow plate, or yellow border. The generated CHR reserves digits 0–9, `%`, `/`, and selected weapons 2–7; BG atlas uses 232/232/227 tiles, sprite atlas 66/66/61, OAM22–24, peak six sprites per scanline. Mesen `RemoveSpriteLimit=false`; Lua PPU dumps verify state changes and BG rendering. All 42 stretched faces contain 576 unique 8x8 tiles before flip-aware packing, so production needs resident subset or safe CHR updates. These are NROM visual playback fixtures, not fc-pico stream/hardware validation.
