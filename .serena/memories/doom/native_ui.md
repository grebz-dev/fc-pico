# Doom native UI invariants

- Engine adapter `doom/rp2040-doom/src/fcpico/ui_capture.c` snapshots semantic status/menu selection; `doom/port/video/fcui.c` packs v4 UI state. `doom/tools/build_native_status_probe.py` builds resident CHR/OAM rendering in the erasable ROM. `doom/sim/mesen2/run_native_status_probe.py` exercises this ROM with synthetic or captured host Doom picture streams. Mesen does not execute the RP2350 engine or prove physical PIO/DMA timing.
- V4 mailbox is 144 bytes; calibrated NES-001 read count is 15122 because 28 native background text tiles are omitted from the picture stream. Preserve the fixed read schedule and permanent fix bank. Protocol fields come from `fcbus_protocol.h`; regenerate derived constants with `gen_protocol.py`.
- NES sprites permit eight entries per scanline and 64 total. Resident `$1800` atlas uses 24 tall-glyph tiles and eleven 3x3 face variants (123 of 128 tiles). The title logo uses 32 tiles at sprite `$1600` (`$60..$7F`). Paused main menu uses a 21-tile, 56x24 logo at `$1130` (`$13..$27`), 28 full-size menu letters, 12 health/armor sprites and one cursor; face, weapons and keys yield slots while paused and return when the menu closes. Static H/R status labels render in the native background stream. Episode paired glyphs use 19 tiles at sprite `$1000` (`$00..$12`) and 21 OAM entries. Both logos derive from `M_DOOM`; a block-letter substitute was rejected. Lower-half CHR art passes Mesen but still needs physical validation.
- Inactive menu packets may retain menu ID=1; gate logo display on the menu-active bit. A stale ID without that gate leaves a yellow logo corner on screen. The full status has six number sprites per scanline, so a 3-sprite-wide face at the same Y would exceed the hardware limit. Face visible y=214..237 sits in a central niche; weapon/key rows are y=216..223 and 224..231, peaking at eight sprites per line. Check all scanlines in Mesen with sprite-limit removal disabled.
- Native status occupies y=192..239, reserves BG palette 3 for dark/gray/light/red backing and native background ammo row 28. During status display, world attribute selection uses palettes 0..2. Sprite text uses red with a dark in-tile shadow. Native menu sprites draw over the world without a black mask. `M_Drawer` suppresses original item labels/skull for native menu IDs 1, 2, 4, 5. Difficulty menu ID 3 keeps Doom's original long styled patches, which remain dithered by the background converter. Dynamic load/save text and other titles still use converted game graphics.
- Editable exact-size PNGs and the import pipeline are in `doom/assets/EDITING.md` and `doom/tools/edit_sprite_sheets.py`; importing updates CHR used by the ROM. Source WHX generators and `export` overwrite manual edits. `doom/tools/preview_native_ui.sh` builds Mesen test scenes without UF2; the GUI shows a repeating captured scene, not a live Doom simulation.
- Physical HR-12 confirmed red text, gray backing and idle/ouch/pickup faces. HR-13 photo showed 9010 alignment issues; HR-14 report showed 9011 stale logo, clipped face and menu text problems. The post-HR-14 changes have only host/Mesen validation so far. See `doom/HARDWARE-LOG.md` for dated evidence. Do not store transient artifact hashes here.

## 9013 concrete HUD candidate (2026-09-29)

- Status painter in `port/video/fcvideo.c` now composes native-resolution concrete, red ammo/health/armor percentages, white AMMO/HEALTH/ARMS/ARMOR labels, and four current/max ammunition rows from a generation-matched `fcui_status_t` captured before conversion. `maxammo[4]` is host-renderer-only; the 16-byte v4 mailbox and read count remain unchanged. The v4 omitted row y224..231 is static: spaces plus four black `#` tiles under the face.
- The face atlas is generated from WHX by `tools/build_large_face_art.py`: ten resident 28x32 expressions within 32x32 cells, 119 unique 8x8 tiles after horizontal/vertical flip deduplication. The most damaged ordinary state reuses the preceding damage frame to fit; god, dead, ouch, grin and three healthy idle expressions remain. `native_status_art.py` maps its 160 face tile references; generated CHR occupies sprite tiles $80..$F6. The status OAM uses slots 0..15 for the 4x4 face, 16..21 for ARMS 2..7, 22..24 for vertical keys. Max scanline occupancy is eight; menu sprites use slots 35..63, and a paused logo temporarily takes slots 0..20 after status sprites yield.
- The resident art and menus moved to erasable PRG bank 1 at $A000; bank 0 holds code. The permanent fix bank remains byte-identical. ROM stamp `20DOOM-04-9013`. Mesen and host tests pass, and a matching WHX UF2 exists in the device build folder. Physical validation remains outstanding.
- Follow-up background-first menu approach is in `plan/12-sprite-ui.md`: composite native glyph pixels into streamed picture tiles after scaling to keep the world visible behind text. Direct nametable glyph replacement cannot make transparent menu text over world. 8x16 is a global PPU sprite-mode change that halves face OAM entries but does not increase the eight-per-scanline bound; test against menu and key art before selecting it.
