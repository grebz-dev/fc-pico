# World sprites (plan 14)

Plans: `doom/plan/14-world-sprites.md` (design, budgets, notes), `14a` (occlusion research), `14b` (probe results); protocol v5 summary in `plan/03-protocol-v2.md`. Live status/evidence: `doom/PROGRESS.md`, hardware request HR-17.

Runtime design (chosen: RP2350 LUT/DDA scaling):
- Protocol v5 keeps v4 stream geometry/count. One acknowledged packet per heartbeat in the mailbox command area (`MBX_FLAG_WORLD`); CHR packets = 4 tiles in the attribute bytes; OAM packets stage 16 entries at console `$0400` and may commit a generation plus sprite palettes 0/2. Heartbeat pad2 = shown gen << 4 | applied seq. `fcbus_core_publish_world()` gates the picture swap on that gen; `fcbus_core_set_mailbox_hook()` lets the scheduler fill packets.
- ROM generator chain ends in `tools/build_world_sprite_rom.py` (stamp 20DOOM-05-9031) on top of the 9016 HUD; device build `tools/build_bg_text_probe_device.sh --native-world` with `FCPICO_WORLD_WAD`.
- 53-tile CHR pool unused by HUD/menu/logo (`FCWORLD_TILE_POOL_INIT`, mirrored by `world_tile_pool()` and tested); world OAM slots 35..63; menu glyphs never borrowed. Menus are released only after world gen 0 and menu palettes are shown.
- `port/video/fcworld.{h,c}` is shared by firmware, host engine and the Mesen cart model (compiled directly into cartmodel). Its heartbeat path is RAM-resident on device and avoids libc.
- Engine: `rp2040-doom/src/fcpico/world_sprites.c` defers eligible actors in R_ProjectSprite, ranks/admits after BSP, rasterizes in pd_end_frame against `pd_world_front_depth` (smaller stored PD scale = nearer; weapon is 0). Admitted actors are never inserted into PD, so background behind them stays intact.
- Atlas v2: `tools/build_world_atlas.py`, keyed by info.h sprite enum/frame/rotation and checked at runtime against engine sprite width/offsets; flash `FLASH_WORLD_ADDR` 0x10280000 (WHX reservation shrunk to 2 MB). Per family: 15 local colours clustered from source colours (chroma-boosted OKLab, near-greys kept neutral, hue-weighted distance), 4-bit texels, two candidate palettes (reviewed `palette_overrides` in `plan/world-sprite-scope.json` first, then a fit that avoids NES olive $08/$18 and teal $0C/$1C), u8 select/map error tables vs 64 NES colours. `--review LUMPS` renders a 3x source/runtime sheet.
- Colour runtime: `fcworld_plan_palettes` loads the nearest families' candidates into sprite palettes 0/2, but only into slots the generation still on screen does not use (commit writes palettes before OAM DMA). `fcworld_frame_build` gives each 8x8 tile the loaded palette 0..3 with least weighted error. Engine glue tracks this via `fcpico_world_note_submitted`.
- BG palettes: default preset `FCVIDEO_PRESET_SHARED_HUD` = `1D 00 30 / 08 18 30 / 00 30 16 / 09 19 30`; the native HUD uses subpalette 2 (`FCVIDEO_HUD_PALETTE`, HUD index order) shared with the world, so the world keeps all four (green returns). The HUD therefore tints with damage/pickup flashes.
- Tiles repeat by design: `fcworld_bounds`/`fcworld_raster_actor` sample in native pixels relative to the patch origin (left/top, rounded) at a scale snapped to `FCWORLD_SCALE_STEPS` (8/octave, integer table, no libm). With the status bar shown, boxes end at line 191 (`FCWORLD_STATUS_START`) so tile overhang never adds to HUD sprite lines (face starts at line 200).
- ROM 9031: a new world packet outranks a pending OAM DMA ($0310 stays set); HUD/commit DMAs run while the RP waits for the shown gen. Tables NMI path is 2198/2200 cycles: no headroom.
- Device submits with `fcworld_submit_held` before the 38 ms conversion; the commit (last OAM packet) waits for `fcworld_release` at publication. Cart model mimics this with `FCPICO_WORLD_CONVERT_BEATS`/`FCPICO_WORLD_EARLY` (`run_world_runtime.py --convert-beats 2 --early`).
- Validation: `sim/mesen2/run_world_runtime.py` (host `--world-dump` recording, cart model `FCPICO_WORLD_SEQUENCE` replay, per-frame exact match). Mesen `takeScreenshot()` at endFrame returns the previous picture: pair screenshot f with state sampled at frame f-1 start; first heartbeat arrives around PPU frame 127.
- Known limit: CHR upload bandwidth (4 tiles/NMI) dominates: Mesen demo-1 replay is 5.62 heartbeats/picture native vs 3.01 streamed with 2-beat modelled conversion (was 6.89 + conversion). Device RAM post-zone headroom is tight (~1.8 KB above minimum).
